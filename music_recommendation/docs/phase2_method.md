# 第二阶段：真实模型与验证协议

本阶段只做训练/验证开发，保持阶段一的数据划分、候选集合、正反馈定义和指标。`phase2.prepare` 只读 train.csv 和 validation.csv，核对其冻结哈希，不读 test.csv。模型和参数选择仍基于验证集；最终测试没有执行。

## 结构与学习目标

| 模型 | 用户侧 | 艺人侧/交互结构 | 数据损失 |
|---|---|---|---|
| BPR-MF | 32维 ID 向量 | 32维 ID 向量，点积 | mean softplus(s_neg − s_pos) |
| NeuMF | 两套独立16维向量 | 独立 GMF 逐维乘积；独立 MLP 输入拼接，32→16 ReLU；融合线性输出 logit | 正例 softplus(−s_pos) 与负例 softplus(s_neg) 的均值 |
| 内容双塔 | 32维 ID 向量→64→32 MLP | 训练标签 TF-IDF→64维稀疏线性映射→ReLU→32维；**没有艺人 ID embedding** | 两塔 L2 归一化后 10×点积，用 BPR 损失 |

EmbeddingBag 是标签稀疏线性映射的实现方式，权重来自训练 TF-IDF，不是把 artistID 改名成内容。两个塔可以独立编码，在评价时先计算全部用户/艺人向量再矩阵乘法；NeuMF 的联合 MLP 则需对用户–艺人对逐批评分。代码从公式自行实现，借助 PyTorch 自动微分，没有复制第三方模型代码或下载预训练权重。

该 NeuMF 是轻量、不预训练的教学再实现，不能宣称复现论文所有训练配置。BPR 与 NeuMF 同时改变结构和损失，不能把性能差全归因于非线性结构。双塔同时增加内容信息、改变结构和分数尺度，也存在多因素归因限制。

## 训练与选择

- CPU PyTorch 2.9.1+cpu；4 个计算线程，不用 CUDA、不用 torch.compile。
- 全部模型每个训练正对每 epoch 采样 1 个负艺人。候选仅为训练出现过且用户训练未见的艺人，均匀拒绝采样；**不查询验证/测试来排除潜在正例**。
- Adam，coupled L2 weight_decay=1e−4，batch_size=1024；数据损失曲线不包含 weight decay 项，不跨模型直接比较损失数值。
- 每模型两组学习率：BPR-MF 0.005/0.01；NeuMF 和双塔 0.001/0.003。维度与结构固定。最多24轮，每4轮用完整验证用户、全目录候选评价；3次评价无超过1e−5的改善即早停。
- checkpoint 只在提升超过1e−5时更新，所以是达到阈值的最好保留点，不严格保证等于全部评价值的数值 argmax。当前日志可核对具体选择。
- seed42 选择每模型学习率；随后固定学习率，对seed43/44重复训练，每个种子仍独立用验证选择停止点。汇总只包含选中配置的3个种子，排除另一学习率的调参运行。
- 三种子均值/标准差描述当前拆分下“重新训练+验证选轮数”的波动，不是固定轮数纯初始化方差，也不能充当独立测试置信区间。候选网格较小，不能据此对整个模型家族作结论。

## 冷项与公平候选

训练零听众艺人不因随机初始化而获得高分。学习模型把其分数设为该用户最低 warm 分数减1；它们仍保留在候选与正例分母中。Popularity/ItemCF 的零训练艺人也会由零分和训练热度 tie-break 自然落在 warm 艺人后。没有偷偷删除困难目标。

训练负例限定 warm catalogue 与评价全目录不是同一个集合，要如实披露。该选择防止“训练零正例但只收负梯度”的艺人得到虚假的个性化学习解释，不解决新物品冷启动。

## 内容特征如何避免答案泄漏

只允许 `(userID,artistID)` 存在于训练集的标签事件；目录外标签排除；同用户重复使用同标签去重。词表按训练艺人文档频次降序选择，最低 df=2、最多2,000标签，同频按数字tagID排序。IDF = log((1+训练出现艺人数)/(1+训练df))+1，空训练文档也计入分母。TF 使用1+log(count)。每艺人保留最高权重32标签后L2归一化，数值 ID 避免猜测标签文本编码。

59,140条标签符合训练对规则；实际保留词表后有52,884条。当前实现有5,628位艺人有内容，12,004位没有。没有内容的艺人统一使用一个 unknown 特征，所以纯内容塔无法区分它们；会依赖统一评分和训练热度tie-break。所有验证冷艺人都缺少可用内容，**不作冷启动能力声明**。

标签事件的日期未用于排序或截止：这是随机偏好恢复而不是时序预测。过滤训练对避免验证/测试目标行为直接进入特征，但不能证明历史时间因果安全。若以后声称预测某个时点，必须另设时间定义和合法可用特征。

## 复现方式与边界

- 全部12次训练：`python scripts/run_phase2.py`。会覆盖 `outputs/phase2` 派生结果。
- 从随包 NPZ 权重重新评分：`python scripts/replay_phase2.py`。禁止pickle，重新构造训练特征并逐模型核对验证指标。
- 第二个 Notebook 默认快速重评分随包权重；把 `RETRAIN_ALL=True` 才重新训练完整网格与3种子。两者区别明确写在 Notebook，不把读取已有训练结果说成重新训练。
- Windows CPU wheel 已从官方来源确认；实际执行仍为 Linux。Windows 安装/Notebook 原生内核验收尚未完成。
- 一张完整 float32 得分矩阵约134 MB，另有模型、优化器、特征、Python/PyTorch运行时开销；不是总内存上限。Windows 性能取决于设备，不能把这里的秒数当承诺。
