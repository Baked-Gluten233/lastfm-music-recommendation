# 三个后续模型：设计，不是已完成实验

**历史说明：本文保留第一阶段的设计依据。第二阶段已真实实现三个模型，实际配置/结果以 phase2_method.md 和 phase2_findings.md 为准；本计划中维度、网格和轮数只是当时建议。**

以下是当前候选路线。指标、曲线、训练耗时全部待真实运行；不能填“预期提升”当实验结果。训练只用同一 train.csv，验证和全目录评价沿用阶段一。模型结构上互相不同，调学习率/维数/负采样率只算模型内部优化。

## Model 1：BPR-MF

- 目标：ItemCF 依赖直接共现，对稀疏邻域可能不足。低秩用户/艺人向量能否捕获间接偏好，是待验证假设，不是现成结论。
- 结构：用户向量 p_u、艺人向量 q_i，分数 p_uᵀq_i；损失 -log sigmoid(s_ui-s_uj)+L2。
- 负采样：仅从该用户训练未观察目录中均匀抽 j，不查看验证或测试来排除“假负例”；报告未观察不等于负反馈的局限。为公平和冷项约束，推荐主训练负例范围为训练中出现过的艺人，并在所有后续模型保持一致；全目录评估不变。
- 建议小网格：维度 32/64、正则 1e-4/1e-3，CPU mini-batch，最大 100 epochs，验证 NDCG@10 早停。先固定一个种子进行调试，再对选中配置运行至少 3 个种子，报告均值/波动。
- 记录每 epoch BPR loss、验证指标与耗时；不承诺超过 ItemCF。训练零样本的艺人不要用随机初始化分数冒充学到的偏好，统一明确冷项回退。

## Model 2：NeuMF

- 目标：验证非线性用户–艺人交互是否有帮助，而不是仅给 MF 更换损失。
- 结构：GMF 分支逐维相乘；独立 MLP 分支拼接 user/item embeddings，经多层非线性；两分支融合输出 logit。若只做点积加 bias，不算 NeuMF。
- 目标：对训练正对和统一采样负对用 BCEWithLogitsLoss。BCE 与 BPR 同时改变使“改进由结构导致”的归因不完全，需在报告承认，预算允许可做 MF+BCE 的内部消融。
- 用户/艺人向量维度从与 BPR 近似参数量的配置开始；MLP 64→32→16，明确是否预训练。未调用论文原代码，因此只能称透明再实现，不声称忠实论文复现。
- 输出学习曲线、过拟合检查、参数量与 CPU 成本。小数据上复杂模型可能更差，照实选择。

## Model 3：内容双塔（特征审计通过后实施）

- 必须是两个可独立编码的塔：用户塔由用户 embedding + MLP 生成向量，艺人塔由训练允许的标签特征 + MLP 生成向量，两塔归一化后点积。不是把两个 ID embedding 改名为“双塔”，也不是 NeuMF 仅加标签列。
- 数据 gate：现有 186,479 条标签记录中有 1,538 条指向目录外 artistID，需先隔离；标签时间是打标签时间，不是听歌时间。tags.dat 的非 UTF-8 文本需检查编码，不能用盲解码后文本含义作结论。
- 防泄漏基准：仅保留 (userID,artistID) 在 train.csv 中的标签事件，按艺人汇聚；不能把全量 user_taggedartists 直接聚合，否则本用户验证/测试艺人的打标签行为可能暴露答案。标签词表、频次筛选、TF-IDF 的 IDF 都仅拟合允许的训练标签。记录保留比例、空内容艺人数、每用户内容覆盖，数据来源不足时暂停此模型而不是造特征。
- 主配置建议：训练标签 TF-IDF，最低训练文档频次 2，词表上限 2,000，艺人塔 linear→ReLU→linear 得 64 维，用户塔 embedding→MLP 得 64 维，BPR/对比损失择一预先固定。训练标签没有对应文本时用明确 unknown 向量。
- 此保守内容规则会使训练完全无交互的新艺人缺少标签。因此**不能声称解决新艺人冷启动**。如要单独研究真正内容冷启动，必须另有独立于目标交互的元数据或专门 donor-user 方案，并单独评测，不能混入主表。
- 用户塔只用 ID 是为避免训练时“历史向量含目标艺人”的自泄漏。如改用历史池化，训练每个样本必须排除目标艺人，并与验证/测试推断规则保持一致。

## 迭代记录与停止条件

每一步填写：前一阶段实际发现 → 机制假设 → 结构变化 → 固定条件 → 超参候选与验证值 → 是否支持假设 → 下一步。当前 ItemCF 对有冷目标用户和低活跃用户表现较弱，且 shrinkage 提高验证指标同时显著降低覆盖率，是值得检验的证据，不足以锁定因果。

完成三个后续模型并不保证最后一个最好。最终按预先指定验证 NDCG@10、稳定性及 CPU 成本决定，覆盖率作为权衡指标。之后才解封测试。课程 bonus 需确认该架构不在课程中，并另有至少三个 MF 及以上对照；当前不宣称满足 bonus。

参考：BPR 原论文 https://arxiv.org/abs/1205.2618 ；NCF 原论文 https://arxiv.org/abs/1708.05031 。实施阶段需进一步核对原文、CPU PyTorch 固定版本和 Windows 支持，不在本阶段安装深度学习依赖。
